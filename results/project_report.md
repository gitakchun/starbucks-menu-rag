## 1. 목표와 범위

고객이 “우유 못 먹는데 뭐 마셔요?”, “카페인 적은 거 있어요?”, “별 적립이 왜 안 돼요?”처럼 일상적인 표현으로 질문하면 스타벅스 코리아의 공개 자료에서 관련 근거를 찾아 안내합니다.

프로토타입은 메뉴·푸드의 상품 설명, Tall 기준 영양·카페인 정보, 상품 페이지의 알레르기 표시, 고객지원 FAQ를 대상으로 합니다. 매장별 실시간 재고, 주문 개인 정보, 교차접촉 여부와 개인별 알레르기 안전성은 제공하지 않습니다.

## 2. 데이터 수집

수집기 `src/collect_starbucks_data.py`는 스타벅스 코리아가 공개한 카테고리별 메뉴 JSON, 상품 상세 페이지의 구조화 JSON-LD, 고객지원 FAQ endpoint를 이용합니다. 상품 코드와 FAQ ID로 중복을 줄이고, 레코드마다 분류·원본 URL·수집 시각을 남깁니다.

2026년 10월 6일 수집 결과는 메뉴 316개와 FAQ 422건입니다. 상품 상세 316건 모두 구조화 데이터를 읽었으며, FAQ 답변 누락은 없었습니다. 재수집은 API 키 없이 가능하고 요청 간격을 두도록 기본값을 설정했습니다.

데이터 파일은 `data/starbucks_knowledge.jsonl`입니다. 공개 웹 정보는 메뉴 개편에 따라 변할 수 있어, 수집 결과는 수집 시점의 스냅샷으로 취급합니다.

## 3. 파이프라인 동작

```text
공식 메뉴·FAQ 페이지
  -> 수집기: JSONL 738건
  -> ingest: LangChain Document 738개
  -> RecursiveCharacterTextSplitter: 450자 / 40자 겹침
  -> 청크 780개
  -> Google gemini-embedding-001
  -> FAISS 벡터 검색
  -> Dense Top-3 또는 Hybrid / Dense 후보 6개 + LLM Reranker Top-3
  -> 근거 제한 Prompt + gemini-3.5-flash-lite
  -> 답변
```

`src/capstone_compare.py`는 Baseline Dense, Dense+BM25 Hybrid, Dense 후보 후 LLM Reranker를 동일한 질문셋으로 비교하도록 구성되어 있습니다. 임베딩·Reranker·답변 생성은 Google Gemini API를 사용합니다.

별도 `src/offline_demo.py`는 API 키 없이 전체 레코드를 읽고 청크를 만든 뒤 한국어 토큰 기반 BM25 Top-3 근거를 보여줍니다. 이 모드는 LLM 답변을 생성하지 않습니다.

## 4. 알레르기 안전 원칙

- 상품 페이지에 알레르기 유발요인이 명시된 경우에만 그 표시를 전달합니다.
- 알레르기 정보 미표시는 “알레르기 성분 없음” 또는 “안전함”으로 해석하지 않습니다.
- 교차접촉, 전체 원재료, 대체유의 알레르기 안전성은 자료만으로 보증하지 않고 매장 파트너 확인을 안내합니다.
- 영양·카페인 수치는 문서에 표시된 메뉴 규격과 함께 전달합니다.

수집 당시 알레르기 표시가 확인된 메뉴는 120개, 별도 표시가 없던 메뉴는 196개였습니다. 미표시 196개를 무알레르기 제품으로 분류하지 않았습니다.

## 5. 검증 결과

| 검증 | 결과 |
|---|---|
| 메뉴 수집기 스모크 테스트 | 공식 상품 2개 수집 및 JSONL 기록 성공 |
| FAQ 전체 페이지 수집 | 8개 고객지원 분류, 422건 수집 성공 |
| FAQ 페이지네이션 | 마지막 페이지까지 읽도록 수정 후 재검증 성공 |
| 전체 JSONL 로딩·분할 | 문서 738개, 청크 780개 |
| FAQ 질문 보존 | 답변이 청크로 나뉘어도 질문 누락 0건 |
| 평가 질문 연결 | 10개 질문, 답변 가능 7개; 기대 키워드 누락 0건 |
| 오프라인 BM25 | API 키 없이 검색 실행 및 공식 출처 출력 성공 |
| 정적 검사 | 수정 Python 파일 문법 검사 및 Pylance 오류 없음 |

**2026-10-07에 전체 평가를 1회 실행했습니다** (`gemini-embedding-001`, `gemini-3.5-flash-lite`, 답변 가능 질문 7개). Retrieval Hit Rate / MRR은 Baseline Dense 1.000 / 0.833, Hybrid 1.000 / 0.810, Reranker 0.857 / 0.786으로, Hybrid와 Reranker 모두 Baseline을 넘지 못했습니다. 근거성 평균은 Baseline과 Reranker 모두 5.00입니다. 거절·직접 답변 지표는 문구 일치 판정의 한계로 신뢰하기 어렵습니다. 상세와 해석은 README 7장과 `results/run_result.md`에 있습니다.

현재 평가 질문은 10개로 초기 회귀 확인용입니다. 포트폴리오 성능 주장을 하려면 메뉴 카테고리와 FAQ 유형을 고르게 포함하는 30~50개 이상의 별도 검증셋이 필요합니다. 알레르기 관련 답변은 자동 Judge만으로 안전성을 입증할 수 없으므로 수동 점검도 요구됩니다.

## 7. 실행 방법

API 키 없이 근거 검색:

```bash
uv sync
uv run python src/offline_demo.py --question "우유 알레르기인데 카페 라떼에 우유가 들어가나요?"
```

공식 자료 갱신:

```bash
uv run python src/collect_starbucks_data.py --delay 0.25
```

전체 임베딩·생성 평가에는 `.env`에 유효한 `GOOGLE_API_KEY`를 설정한 뒤 실행합니다.

```bash
uv run python src/capstone_compare.py
```
